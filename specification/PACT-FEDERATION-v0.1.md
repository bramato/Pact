# PACT Federation v0.1 — draft building blocks

Federation is an optional profile of Core 0.2 over A2A 1.0, identified by this document's URL. A coordinator is authoritative for a personal federation and distributes an authenticated, revisioned roster with an MCP endpoint. Roster membership permits chat with active members; it does not grant file, tool, or other users' conversation access. Peer credentials and MCP credentials have distinct audiences. External agents retain stable product/user identities; conversations are private and are not mirrored.

The `federation-roster` and `federation-delegation` schemas describe preliminary wire resources. IDs are stable and member IDs unique. The delegation path must contain unique identities and at most four entries; the root budget allows at most eight delegations, sixteen steps and five minutes. Implementations must enforce the deadline and shared budget transactionally across the whole root, reject nested Swarm, cancel descendants and record late observations without reviving canceled tasks. Individual Core tasks have distinct root, parent and delegation identifiers.

Every exchange requires a durable ledger entry committed before delivery, with an outbox, receipts and replay/idempotency checks. Delegation must return an immediate receipt and atomically persist its checkpoint, wait state and outbound work before continuation. Bootstrap and roster refresh require authentication and revision/ETag handling; membership changes must take effect for subsequent authorization checks.

The planned MCP methods are `list_members`, `get_manifest`, `send_message`, `request_delegation`, `get_task`, `read_conversation`, and `reserve_step`. Input contracts are defined below. Complete result contracts, transport, scheduling and full conformance remain work in progress. The provided SQLite ledger is a building block, not a complete Federation implementation.

## Bootstrap and authorization contract

A trusted coordinator URL is configured out of band. The host verifies the issuer's signature and token validity before passing claims to the policy; the policy additionally requires the exact expected issuer and scalar audience, nonempty subject, unexpired `exp` and valid `nbf`. MCP and peer endpoints MUST use distinct audiences and MUST NOT accept a token intended for the other endpoint. An authenticated bootstrap or refresh returning 200 supplies a roster and a strong ETag formed as a quoted lowercase SHA-256 of the JCS roster. A conditional refresh may return 304 only when the local roster and requested ETag match. The federation ID and coordinator URL cannot change, revisions cannot decrease, and equal revisions must have identical content. Persist a new roster and its revision atomically; recheck active membership for each request. TLS and authentication are the host transport's responsibility.

A stable published external agent ID is `agent_` followed by SHA-256 of the UTF-8 byte-length of the product ID in decimal, a colon, then the product ID and user ID. This identifies an agent, not a session. A conversation stays in its owner's application; a host MUST authorize every `read_conversation` against its actual participants, and MUST authorize task reads and manifest visibility according to resource ownership. The roster grants no general access to these resources. The SDK policy only performs its stated checks; the host supplies verified claims, durable state and resource-specific authorization.

## MCP host interface

Each method has an object input with no extra properties. All identifiers and text are nonempty strings. `list_members` accepts `{}`; `get_manifest` accepts `{member_id}`; `send_message` requires `{id, recipient_id, text}` and optionally accepts `conversation_id`, `kind` (`request`, `reply`, or `notification`, default `request`), and `task_id`; replies and notifications require a conversation; `request_delegation` accepts `{id, recipient_id, task_id, input}` with object `input`; `get_task` accepts `{task_id}`; `read_conversation` accepts `{conversation_id}`; `reserve_step` accepts `{task_id, step_id}` and atomically reserves one model call against the shared root budget, with `step_id` scoped to the caller for idempotency. Host results are application-defined pending a versioned result contract. A write `id` is an idempotency key scoped to federation and actor. A changed request with the same key MUST fail, while an identical request MUST return the originally committed result without executing a second time. Delegation returns an immediate durable receipt; it MUST NOT synchronously wait for completion.

`Pact\\Federation\\McpDispatcher` checks membership and input shape, then calls `Runtime` in a transaction. For writes, the runtime must atomically append the immutable exchange and pending delivery before invoking host logic, save the result in the same transaction and make it visible only after commit. The host's transaction MUST roll back all state if any operation fails. The runtime must enforce resource authorization and prevent outbound delivery until after commit. `checkpoint` is a persistence port: host implementations MUST atomically record the root budget, waiting state and continuation with outbound messages, apply cancellation to descendants, record late observations without resuming canceled tasks and reject nested Swarm. These guarantees cannot be inferred from a PHP interface alone and require implementation-level tests.

`SqliteRuntime` supplies a reusable transactional implementation of the persistence port. Applications subclass it to implement `invoke` and their authorization and execution logic. Its pending-delivery reader is available only after commit; acknowledgment persists a receipt and rejects conflicting receipts. A worker must deliver idempotently and manage its own concurrency, retry scheduling and leases. The adapter does not implement the delegation state machine, transport or MCP authentication on the host's behalf.

Roster member records may additionally carry nonempty `name`, `specialization`, `agent_id` and `origin` fields. Production coordinator and MCP URLs use HTTPS. For local development only, hosts may configure an explicit allowlist of `.test` or loopback hostnames; only those listed hosts may use HTTP. The default allowlist is empty and public HTTP hosts remain forbidden even if listed. Both URLs are checked. No TLS exception may be inferred from the roster itself.

`DelegationState` supplies pure root-scoped transitions for step and delegation budgets, paths, descendant cancellation and late observations. Its maximum path length is four member identities, including the root member. The host MUST load, transition and save the root state in one transaction with its outbox, and ensure only authenticated actors can request transitions. In-memory transitions alone do not provide concurrency control or delivery.
